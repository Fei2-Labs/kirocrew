## Errors & Lessons (read before touching conflicts)

- **NEVER `git checkout --theirs` on a conflicted file** as a shortcut — it
  silently discards fork content that auto-merged OUTSIDE the conflict hunks
  (damaged app-kit-platform 39 lines / README 11 / metrics 2 / mirrors 1 before
  an audit caught it; those particular deltas proved droppable, but the trap is
  real). Resolve hunks surgically, or take-theirs-then-reapply-fork-delta.
- **A "moved elsewhere" hunk can still carry fork rows.** Taking theirs on a
  relocated-table hunk in `backends.py` dropped copilot's
  `ACP_BACKEND_PROCESS_NAMES` row → `KeyError: 'copilot'` at import. Check
  symbols, not just shape.
- **Upstream dissolved big modules into facades + `*_parts/` packages.** Most
  large conflicts are "fork monolith in ours-block vs empty theirs" — the code
  moved; take upstream structure and port the fork delta into its new home
  (`deny_gate.py`, `denied_rules_catalog.py`, `paths_lists.py`,
  `governance_parts/tool_calls.py`, `validation_parts/*`, `conftest_floor_*`).
- **Never resolve JSON by hunk fragments** — a fragment script corrupted 2
  locale files (markers stripped but malformed). `git checkout -m` restores
  markers; whole-file recursive merge on `:2:`/`:3:` index stages is the safe
  approach (script at `/tmp/union-locales.py`, `/tmp/merge-locale.py`).
- **Fork-delta sizing:** `git diff <merge-base>..main -- <file>` shows the true
  re-apply delta; conflict-hunk count per file is the effort metric (464 hunks
  across 183 files at measurement time).
- pytest import-driven discovery is too slow for 150+ files — batch by
  subsystem using delta analysis instead.
- Merge-base deltas include everything the Sept sync already absorbed — raw
  delta size overstates remaining effort.
